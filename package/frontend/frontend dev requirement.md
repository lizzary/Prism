# Prism项目介绍  
  
经常在fanbox、pixiv下载和收藏插画，或者使用comfyui以生成大量图像、视频的用户经常会遇到一个问题，就是现有的资源管理器以目录的形式管理文件，而图像文件的分类极其丰富（特别是comfyui这种每个图像文件都有不同的提示词、种子等），因此光分类就可能有几十个种类，一般来说你只能在资源管理器中新建几十个目录，非常的繁琐；同时目录在资源管理器中只会显示一个file图标，除非你手动打开它，否则你不知道里面的图像等文件的细节；如果同时想要在目录之间进行图片转移，也要在几十个目录，好几层嵌套中进行来回跳转；更是不支持tags搜索、关键词搜索等。而Prism项目的宗旨就是，提供完善的文件管理系统，优秀的图像/视频欣赏体验，数据安全以及能够接入agent帮忙管理图库，让用户即使在面对万张、十万张图片、视频也能轻松的管理，有良好的欣赏体验

项目技术栈采用ReactJS前端+go后端+sqlite数据库

# 概念
图库：即本项目
文件：图像文件或视频
主页：用户看到的第一个页面，有星月夜的那个
分组：由用户创建，首页的一张封面卡，是文件的实际归档容器，分组里就是具体的图像文件或视频，类似资源管理器的目录的概念，点进去后会展示所有的文件
颜色组：在分组里面的二级组织架构，颜色组按照页面排列方式进行排列（详见下文），同一颜色组的文件会排列在一起，一个可行的视觉效果是所有同一颜色组的文件的背景均被一个半透明的矩形包着，一个分组能有多套颜色组配置，并且能够自由切换
文件浏览页/预览页/分组页：点进分组之后的页面，展示了所有的文件
文件灯箱页面：在浏览页中点击某个文件后打开的页面

### 图像&视频文件浏览页（点击分组后进入）

- 原比例切换的交互，默认为开，当用户开启原比例时，所有文件都会按照原始比例呈现，关闭时则中心裁切为正方形
- 有上传入口，点击后打开本地资源管理器，允许用户上传图像以及视频类型的文件
- 有页面排版交互，用户可以选择单行、双行以及混合排列，页面排版主要控制的是颜色组的排版，对于单行，颜色组按照一维方式排列；对于双行，一行会由两个颜色组平均分，按照第一行左半->第一行右半->第二行左半->第二行右半的部分排列；对于混合排列，颜色组会按照单行排列，但是在该颜色组的末尾，会紧接着另一个颜色组，哪怕它们处于同一行，例如：
	- 每个颜色组只展示10张插画，现在有20个颜色组，对于单行，插画尺寸为让每行只能放5个插画，那么整个页面就是前两行为第一个颜色组，第2-4行为第二个颜色组，以此类推
	- 每个颜色组只展示1张插画，现在有20个颜色组，插画尺寸为让每行只能放5个插画，那么第一行就有5个颜色组，第二行是另外5个，以此类推，对于跨行的颜色组，你应该设计一个漂亮美观的方式来向用户呈现这个颜色组上一行的尾部和下一行的头部是同一组（因为跨行了）
- 有另一个排版交互，用户可以选择每组限量以及全部展示之间切换，对于每组限量，用户可以选择每组展示只展示x个文件，对于全部展示就是每组都完整的展示所有文件
- 对于每个颜色组，如果颜色组处于每组限量的状态时，那么用户可以选择将该组完全展开（其他分组不受影响）以及收起到每组限量的那个值两个状态之间切换
- 对于每个颜色组，用户可以选择收起这个颜色组或者展开这个颜色组，展开后的颜色组固定按照当前页面排版的设置来
- 有一个交互能够实现在收起所有分组和展开所有分组之间切换
- 有一个交互能让用户选择每页展示多少个文件，默认为全部，档位有50、100、200、500、1000、全部
- 页面上方下底部都有分页交互（如有有分页），上方的安静小巧一点
- 用户可以拖动插画来进行排序，当用户拖动插画排序后自动将排序方式切换到自定义排序，当前排序会直接保存在自定义排序中，如果用户将一批插画拖动到同一个颜色组的位置，那么直接生效，如果用户将一批插画拖动到一个位置时，而对于该位置有任意一个插画原始的颜色组与该位置所属的颜色组不同时，那么会出现弹窗，显示拖动前后的差异以及让用户二次确认
- 用户可以拖动颜色组来进行排序，该排序会直接保存为颜色组排序（和颜色组配置页面里拖动一样）
- 有设置入口，能够打开悬浮设置表单  
- 有导出入口，用户打开后是一整套的分组页导出配置页面   
- 有搜索入口，用户可以设置搜索域（可多选），可以搜索分组、颜色组、tags、正向提示词、负向提示词、以文搜图、以图搜图，以文搜图和以图搜图只有在后端具备某些条件时才解锁，否则处于锁定状态，支持并集，文件预览页的搜索的搜索域分组默认填充为当前分组
- 支持拖动上传，但是拖动当前分组内的文件时不会触发拖动上传

- 支持ctrl选中以及shift选中，对于被这两个批量选中方式选中的文件，需要有交互让用户删除这些文件、下载这些文件、重新索引这些文件，删除需要二次确认
  
  
### 灯箱页（在分组页点击某个文件后进入）
至少需要具备以下元素/交互：

# 白板（在文件浏览页中进入）
白板是该分组的可视化：
- 无限延申
- 左键框选、右键拖动白板，滚轮缩放白板
- 有交互能让用户回到中心并重置缩放
- 如果当前分组有颜色组，那么展示所有颜色组
- 用户与白板上的颜色组进行交互来编辑该颜色组
- 如果当前分组有文件，那么以一个正方形迷你小卡的方式在白板中展示，对于有颜色组的文件，该小卡会出现在对应的颜色组
- 用户可以框选并拖动一批小卡来进行：改变颜色组（从某处拖动到颜色组内或者从某处拖动到外部来让这批文件不属于任何颜色组）、删除这些文件、下载这些文件、重新索引这些文件，全部无需二次确认
- 支持ctrl选中
- 当鼠标悬浮在小卡上时，按照该卡的文件的原始比例展示该卡的浮窗，小卡固定使用“中”档位的画质，浮窗使用的画质选项与分组设置一致
- 实现两个白板渲染器，一个是WebGL，另一个是DOM，WebGL性能较好，但是不是所有设备都能开启

对于页面排序等页面设置与导出配置等一些只影响前端视觉效果的配置项，为了防止与后端通信带来的交互延迟感，采用乐观更新，前端发生交互时，立刻在前端做出响应，无论请求是否被后端接收到，下一次标准的页面状态更新会使用后端提供的新配置，例如用户退出该页面后又重新进入或者刷新页面等（即不为同步设置项而专门设置状态更新点）  
  
### 前端开发要求  
1. 前端使用最新版的React+Js开发  
2. 重要：美术设计、ui、布局、交互与动画效果需要是生产级的，精致美观有设计感的，禁止demo质感、廉价的塑料质感以及用烂了的布局设计；需要让人有种，页面的呈现很精致、每一处人机交互、动效都透露着精品的感觉；在交互上要有细节、有小巧思；用户光是和页面交互就很有意思，愿意让用户驻足互动，而不只是干枯无聊的数据dashboard，用完直接alt+F4关掉就行。因此每处控件、组件与布局设计都应该仔细斟酌，这样设计符不符合质感要求，用户观感、体验怎么样  
3. 项目语言：和原项目一致
4. 允许使用少量圆角，但不要滥用圆角；禁止珠光感；主配色使用相对温和对比度的方案，让人看上去颜色相对柔和、温柔
5. 项目文案：使用prism项目的文案、正常的文案，例如新增分组功能就是“新增分组”，而不是“新增回忆”之类的乱七八糟的文案，不要那种为了贴合项目主题所产生的奇怪的文本文案  
6. 不要使用默认字体！  
7. 在任何情况下都绝对禁止使用emoji，需要用图标的地方，你需要自行绘制本项目专用、风格统一、精致美观的图标，如果原项目的图标合适那么你也可以沿用原项目的图标，该图标也会作为项目的图标库中的成员方便复用  
8. 尽可能少的在前端出现小字注释  
9. 布局、交互的设计在符合页面主题的情况下，鼓励更富有创意的交互  
10. 前端使用ui数据分离架构，即ui层里不做任何后端逻辑，例如发送请求，解析后端数据等（前端、页面、交互、渲染等只涉及前端的逻辑是可以的），ui层专注做ui、交互设计；数据层专门对接前端和后端，数据层负责和后端交互、处理数据、业务逻辑，所有ui层需要的后端相关的api均在数据层内实现，并由数据层暴露给ui层，ui层里只调数据层的api，如有需要也可以用一个中建材连接ui以及数据层  
11. 本轮先完成全部ui的设计与绘制，所有数据直接硬编码在代码里即可，暂时不需要对接任何真实后端api
